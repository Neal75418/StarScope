# 設計決策紀錄

`specs/` 底下是各功能**定案當下**的設計文件，記錄取捨與理由。

**這些文件不隨程式碼更新，也不該更新。** 它們寫的是「某年某月某日，在當時
的量測與限制下，我們決定了什麼、放棄了什麼」——那是歷史，不會過期。
系統現在長什麼樣，以程式碼為準；跨層約定與路徑陷阱見 `CLAUDE.md`。

所以讀到與現況對不上的敘述，多半不是錯的，是當時的問題陳述。例如
`2026-08-16-star-sync-design.md` 開頭說「app 裡有 1 個 repo」——那正是
當初要解決的問題，不是在描述現在。

同理，spec 裡設計了但沒實作的部分（例如 for-you-feed 的 Phase B 影子池）
不是缺陷，是一份有效但尚未被執行的設計。

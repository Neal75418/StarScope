# Star 同步實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓追蹤清單成為 GitHub star 的鏡像——開 app 自動對一次，app 內的加入與取消會寫回 GitHub，取消的 repo 封存而非刪除。

**Architecture:** `repos` 加兩個可為空欄位（`unstarred_at`、`starred_at`），並用 SQLAlchemy 的 `do_orm_execute` 事件讓「排除封存」成為所有 SELECT 的預設，需要看到封存資料的地方顯式 opt-out。同步以 `github_id` 比對遠端與本機，算出新增／復原／改名／封存四個集合。所有建立 repo 的端點在建立前先 star，確保沒有任何路徑能產生未 star 的列。

**Tech Stack:** Python 3.13 / FastAPI / SQLAlchemy 2.0.46 / SQLite・React 19 / TanStack Query v5 / Vitest / Playwright

**Spec:** `docs/superpowers/specs/2026-08-16-star-sync-design.md`

**狀態：九個任務全部完成並上線。** 以下記錄執行時偏離計畫之處，以及計畫沒能預見的
事。spec 已回頭更新為實際交付的樣子；這份計畫保持原樣，只加這段後記——計畫的價值
在於它當初怎麼想，改寫它就看不出哪裡想錯了。

### 偏離計畫的三處

| 計畫寫的 | 實際做的 | 為什麼 |
|---|---|---|
| Task 6 先量測 GitHub 寫入的次級限制，再寫死間隔 | 改讀回應的 `Retry-After` 退避 | 那是被限流當下的真實答案，而量測會對使用者的真實帳號連打上百次寫入 |
| Task 5 的 `resolve` 只支援 `archive` | 兩個動作都支援 | Task 6 的推送上線後補齊，計畫已預留這一步 |
| Task 2 只列了五個 opt-out 位置 | `find_similar_repos` 與 `get_personalized_recommendations` **各要一處**，計畫只寫了一處 | 相似度快取有兩個消費端，實作時才發現 |

### 計畫沒預見、但實作時必須處理的

- **無 token 時的寫入**：計畫假設一律能寫 GitHub。實際上 star 需要認證而讀取不需要，
  硬性要求會讓未連結帳號的使用者連新增都做不到，也讓 CI 的 e2e 無法建立測試資料。
- **封存後如何再追蹤**：計畫只交代存在性檢查要看得見封存列（避免撞唯一鍵），沒交代
  看見之後該做什麼。回 400 等於把取消過的 repo 永久擋在門外。
- **e2e 的清理**：`removeRepoByFullName` 直接 `DELETE`，而 DELETE 改成只接受封存的
  之後它會靜默失敗，把狀態留給下一個測試。
- **同步鎖的生命週期**：計畫用布林旗標。sidecar 是 Tauri 的子行程會被殺，旗標於是
  永遠留著。

### 一條計畫裡的測試本身是錯的

Task 2 的測試以 `/api/repos/{id}/similar` 為目標——**那支端點不存在**。真正的消費端是
`find_similar_repos()` 與 `/api/recommendations/personalized`。

### 上線後才顯現的問題

有六項通過了全部測試與 CI，卻在第一次真實操作時就顯現。它們的機制與「為什麼測試看
不到」記在 spec 的「只有真實使用才會發現的」一節。

## Global Constraints

- 比對鍵一律是 `github_id`，不是 `full_name`。`full_name` 會因 repo 改名而變動。
- 封存＝寫入 `unstarred_at`，永遠不刪除快照或訊號。唯一的硬刪路徑是封存清單裡的「永久刪除」。
- 推送順序永遠是「先寫 GitHub，成功後才改本機」。
- 新欄位透過 `db/database.py` 既有的 `_ADDITIVE_COLUMNS` / `ensure_columns()` 進到既有資料庫。**不要引入 alembic。**
- 後端測試指令：`cd sidecar && .venv/bin/python -m pytest tests/ -q`。CI 另跑 `mypy . --config-file mypy.ini` 與 `--cov-fail-under=85`，覆蓋率餘裕很小，新程式碼必須有測試。
- 前端：`npx vitest run`、`npx tsc --noEmit`、`npx eslint src --max-warnings=0`。
- 每個破壞性或對外的行為都要有 mutation 驗證：把實作弄壞，確認對應測試轉紅，再還原。**還原不可用 `git checkout`**（會洗掉未提交的實作），用檔案備份比對。

```python
"""讓「排除已封存的 repo」成為所有 SELECT 的預設。

為什麼不是在每個查詢加條件：repo 的查詢點有 29 處，而且需要相反的行為——
列表與計數必須排除封存的，依 full_name 或 id 的查找卻必須找得到它們（否則重新
star 時會撞上 full_name 的唯一鍵回 500）。在 29 個地方各判斷一次，漏一個就是滲漏。
把預設反過來之後，要記得的地方只剩下少數需要 opt-out 的查詢。

只攔截 SELECT。bulk delete/update 不受影響——「清空所有資料」必須真的清空。
"""
from typing import Any

from sqlalchemy import event
from sqlalchemy.orm import Session, with_loader_criteria

from db.models import Repo

INCLUDE_ARCHIVED = "include_archived"


def install_archive_filter() -> None:
    """註冊事件。應用程式啟動時呼叫一次；重複呼叫是安全的。"""
    if getattr(install_archive_filter, "_installed", False):
        return

    @event.listens_for(Session, "do_orm_execute")
    def _exclude_archived(state: Any) -> None:
        if not state.is_select or state.execution_options.get(INCLUDE_ARCHIVED):
            return
        state.statement = state.statement.options(
            with_loader_criteria(Repo, Repo.unstarred_at.is_(None), include_aliases=True)
        )

    install_archive_filter._installed = True  # type: ignore[attr-defined]


def include_archived(query: Any) -> Any:
    """讓這一次查詢看得到封存的 repo。"""
    return query.execution_options(**{INCLUDE_ARCHIVED: True})
```

```python
def get_repo_or_404(repo_id: int, db: Session, allow_archived: bool = False) -> Repo:
    """依 ID 取得 repo，不存在則拋出 404。

    allow_archived 供封存清單的檢視與復原使用——預設過濾會讓封存的 repo 一律 404。

    query = db.query(Repo)
    if allow_archived:
        query = include_archived(query)
    # noinspection PyTypeChecker
    repo: Repo | None = query.filter(Repo.id == repo_id).first()
    if not repo:
        raise HTTPException(status_code=404, detail=ERROR_REPO_NOT_FOUND)
    return repo
```

```python
"""追蹤清單與 GitHub star 的同步。

比對鍵是 github_id 而非 full_name：repo 在 GitHub 上改名時 full_name 會變、
github_id 不變，用 full_name 比對會把改名判成「舊的消失 + 新的出現」，於是封存舊列
並建立新列，歷史快照從此斷成兩截。
"""
from dataclasses import dataclass, field
from datetime import datetime

from db.models import Repo


@dataclass
class RemoteStar:
    github_id: int
    full_name: str
    owner: str
    name: str
    starred_at: datetime | None
    payload: dict


@dataclass
class SyncDiff:
    added: list[RemoteStar] = field(default_factory=list)
    restored: list[tuple[Repo, RemoteStar]] = field(default_factory=list)
    renamed: list[tuple[Repo, RemoteStar]] = field(default_factory=list)
    archived: list[Repo] = field(default_factory=list)


def diff_starred(local: list[Repo], remote: list[RemoteStar]) -> SyncDiff:
    """算出本機要做哪些改動才會與遠端一致。不做任何寫入。

    local 必須包含已封存的列，否則重新 star 會被誤判成新增。
    """
    by_id = {r.github_id: r for r in local if r.github_id is not None}
    diff = SyncDiff()
    seen: set[int] = set()

    for star in remote:
        seen.add(star.github_id)
        existing = by_id.get(star.github_id)
        if existing is None:
            diff.added.append(star)
            continue
        if existing.unstarred_at is not None:
            diff.restored.append((existing, star))
        if existing.full_name != star.full_name:
            diff.renamed.append((existing, star))

    for repo in local:
        if repo.github_id not in seen and repo.unstarred_at is None:
            diff.archived.append(repo)

    return diff
```

```python
    async def get_user_starred_with_dates(self) -> list["RemoteStar"]:
        """取得 starred repos，含 star 的時間。

        starred_at 只在帶這個 Accept header 時回傳，而它錯過同步當下就補不回來——
        它是「收藏多久」的唯一來源，added_at 在批次同步後全部是同一天。
        """
        from services.star_sync import RemoteStar

        stars: list[RemoteStar] = []
        page = 1
        while page <= 50:
            response = await self._client.get(
                f"{GITHUB_API_BASE}/user/starred",
                params={"per_page": 100, "page": page},
                headers={"Accept": "application/vnd.github.star+json"},
            )
            data = self._handle_response(
                response, raise_on_error=True, context=f"user/starred?page={page}")
            if not data:
                break
            for entry in data:
                repo = entry.get("repo", entry)
                stars.append(RemoteStar(
                    github_id=repo["id"],
                    full_name=repo["full_name"],
                    owner=repo["owner"]["login"],
                    name=repo["name"],
                    starred_at=_parse_iso(entry.get("starred_at")),
                    payload=repo,
                ))
            if len(data) < 100:
                break
            page += 1
        logger.info(f"[GitHub API] 已取得 {len(stars)} 個 starred repos（含日期）")
        return stars
```

```python
def _parse_iso(value: str | None) -> datetime | None:
    if not value:
        return None
    try:
        return datetime.fromisoformat(value.replace("Z", "+00:00")).replace(tzinfo=None)
    except ValueError:
        return None
```

```python
import json
import logging

from sqlalchemy.orm import Session

from db.models import AppSettingKey, Repo
from db.soft_delete import include_archived
from services.settings import get_setting, set_setting
from utils.time import utc_now

logger = logging.getLogger(__name__)


@dataclass
class SyncResult:
    added: int = 0
    restored: int = 0
    renamed: int = 0
    archived: int = 0
    skipped_reason: str | None = None


def _repo_from_star(star: RemoteStar) -> Repo:
    """直接用 starred 回應建列。

    不要再對每個 repo 呼叫一次 get_repo——首次同步有九十幾個，那是九十幾次額外請求，
    而且會和 main.py 啟動時已經觸發的 trigger_fetch_now() 撞在一起。
    """
    p = star.payload
    return Repo(
        owner=star.owner, name=star.name, full_name=star.full_name,
        url=p.get("html_url") or f"https://github.com/{star.full_name}",
        description=p.get("description"), github_id=star.github_id,
        default_branch=p.get("default_branch"), language=p.get("language"),
        topics=json.dumps(p.get("topics", [])) if p.get("topics") else None,
        starred_at=star.starred_at,
    )


async def sync_starred_repos(db: Session, github) -> SyncResult:
    """把本機追蹤清單對齊 GitHub 的 star。"""
    if not get_setting(AppSettingKey.GITHUB_TOKEN, db):
        return SyncResult(skipped_reason="no_token")

    if get_setting(AppSettingKey.STAR_SYNC_RUNNING, db):
        return SyncResult(skipped_reason="already_running")

    set_setting(AppSettingKey.STAR_SYNC_RUNNING, "1", db)
    try:
        try:
            remote = await github.get_user_starred_with_dates()
        except Exception as e:
            logger.warning(f"[Star 同步] 取得 starred 失敗，不執行任何移除: {e}")
            return SyncResult(skipped_reason="fetch_failed")

        if not remote:
            logger.warning("[Star 同步] 回傳 0 筆，不執行任何移除")
            return SyncResult(skipped_reason="empty_response")

        local = include_archived(db.query(Repo)).all()
        diff = diff_starred(local, remote)

        for star in diff.added:
            db.add(_repo_from_star(star))
        for repo, star in diff.restored:
            repo.unstarred_at = None
            repo.starred_at = star.starred_at
        for repo, star in diff.renamed:
            repo.full_name, repo.owner, repo.name = star.full_name, star.owner, star.name
        for repo in diff.archived:
            repo.unstarred_at = utc_now()

        db.commit()
        set_setting(AppSettingKey.LAST_STAR_SYNC_AT, utc_now().isoformat() + "Z", db)
        return SyncResult(added=len(diff.added), restored=len(diff.restored),
                          renamed=len(diff.renamed), archived=len(diff.archived))
    finally:
        set_setting(AppSettingKey.STAR_SYNC_RUNNING, "", db)
```

```python
對同一個 repo 反覆 star（PUT 是冪等的，重複 star 不會改變狀態），記錄開始被限流的

import time

import httpx
import keyring

TARGET = ("octocat", "Hello-World")  # 執行前改成你已 star 的某個 repo


async def main() -> None:
    token = keyring.get_password("starscope", "github_token")
    async with httpx.AsyncClient() as c:
        for i in range(1, 101):
            r = await c.put(
                f"https://api.github.com/user/starred/{TARGET[0]}/{TARGET[1]}",
                headers={"Authorization": f"Bearer {token}"},

            print(i, r.status_code, r.headers.get("retry-after"),
```

第三欄必須大於 0——封存不得刪除快照。
